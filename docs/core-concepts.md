# 需要本人理解的核心代码

## 1. 行列与方向

棋盘坐标使用 `(row, col)`：行号从上往下增加，列号从左往右增加。

```python
DIRECTION_STEPS = {
    "U": (-1, 0),
    "D": (1, 0),
    "L": (0, -1),
    "R": (0, 1),
}
```

所以“向上”不是 y 坐标加一，而是行号减一。

## 2. 为什么边缘朝外箭头一定能飞出

`first_blocker()` 先计算前方第一格，只在该坐标仍在棋盘内时才访问数组。最上方的向上箭头下一步是 `row=-1`，不在棋盘内，循环根本不会进入，因此返回“没有阻挡”。

这里必须“先判边界，后访问”。否则 Python 中的 `board[-1]` 不会报错，而会错误地访问最后一行。

## 3. 为什么飞出动画中的箭头不能继续阻挡

点击成功后，`GameState.click()` 立即将该格改成 `None`。界面层单独保存一份动画快照，把箭头画出棋盘。

这样逻辑和视觉各司其职：

- 逻辑上，箭头已经消失，后面的箭头不再被它阻挡。
- 视觉上，玩家仍能看到完整的飞出动画。

## 4. 如何验证关卡可通关

`solve_board()` 每轮找到一个当前路径畅通的箭头并移除。移除箭头只会减少阻挡，所以：

- 如果能一直移除到空棋盘，就得到一个通关顺序。
- 如果棋盘仍有箭头，但已经没有任何箭头能飞出，则存在相互阻挡的死局。

本项目的第 2 关初稿就曾被这个检查发现死锁，修改一个边缘箭头的方向后才通过全部测试。
